### Expected JSONL schema

Field names are **auto-detected, not hardcoded**.

- **Code field** — first present of: `func`, `code`, `function`, `source`, `func_before`
- **Label field** — first present of: `target`, `label`, `vul`, `is_vulnerable`, `vulnerable`

Labels must coerce to `0` or `1`:

```
0 = benign / non-vulnerable
1 = vulnerable
```

Any other value is **counted and dropped**, not silently accepted.

Metadata carried through preprocessing when present: `project`, `commit_id`,
`cwe`, `cve`, `idx`, `big_vul_idx`, `hash`.

*Consequence:* a PrimeVul export using different column names still works, and
`inspect_dataset` prints which fields it detected — so this is verifiable rather
than assumed.

### Preprocessing workflow

| # | Stage | I/O |
|---|---|---|
| 01 | `inspect_dataset` | raw → stdout report |
| 02 | `validate_dataset` | raw → exit code + leakage report |
| 03 | `preprocess_primevul` | raw → `data/processed/` |

| 05 | `chunk_dataset` | processed → `data/chunked/` |
| 06 | `training.train` | chunked → `data/checkpoints/` |

`data/raw/` is opened **read-only** at every stage. Nothing in the module writes


Expected after the fix: a `+cu121` version string, a CUDA version, and `True`.
This is roughly a 2.5 GB download — **not started without approval**.

### Capacity warning — 4 GB VRAM is tight for CodeBERT

Rough fp32 budget:

| Component | Size |
|---|---|
| Weights | ~0.50 GB |
| Gradients | ~0.50 GB |
| AdamW m + v | ~1.00 GB |
| **Steady state** | **~2.00 GB** |
| Remaining for activations | ~1.8 GB |

Expected working configuration, to be **measured** at Stage 11 rather than
assumed:

```bash
--batch-size 2 --chunk-micro-batch 4 --grad-accum 4
```

That gives an effective batch of 8 with AMP and gradient checkpointing both
enabled. If Stage 11 shows OOM on long multi-chunk functions, the next lever is
reducing `CODESENTINEL_MAX_CHUNKS` from 8.
